# E2E review: runtime answer path (retrieval, agent, validation, MCP)

Reviewer scope: retrieval (BM25 / dense / hybrid / r3), chunking, embedding cache, LangGraph agent and guards, tools, deterministic calculation, T-I06 crosscheck, answer schema and validators, abstain / clarify / refuse, timeouts and retries, trace emission, MCP server and client.
Method: code tracing, read-only Python snippets against the real local corpus (16,419 passages, 1,847 `merge200` chunks, 4,300 in-scope observations), scripted `llm.chat` doubles, and the saved runs in `data/runs/agent/`. No network or model calls were made. `pytest -q -m 'not corpus'`: **535 passed, 54 deselected** (observed). Smoke script: `/tmp/smoke_rev.py` (not committed). Labels: **[F]** fact observed, **[I]** inference.

## 1. The flow as traced

1. `report/app.py` `POST /api/ask` (`report/app.py:~370`) admits the request and calls `agent.graph.run_agent(question, Shared)` in a thread. `Shared` (`agent/tools.py`) loads `load_world()` (`retrieval/runtime.py`): passages (`data/passages/*.jsonl`), `merge200` chunks, an in-memory BM25 index built at startup, and a dense index of `text-embedding-3-large` vectors read from `data/index/embeddings/.../cache.npz`. [F] The cache covers all 1,847 current chunks (0 missing), so startup is offline-safe.
2. `build_graph` compiles seven nodes: `validate_question` (1–1000 chars; injection flags are traced only, never block) → `plan_research` (planner LLM, schema-constrained enums, ≤3 calls/round, ≤2 rounds, ≤6 calls) → `execute_tool` (worker pool, 10 s per call, one retry only for `TransientToolError`) → `assess_evidence` (crosscheck annotate) → `generate_answer` → `validate_answer` (crosscheck enforce + `validate.check`, one repair) → `finalize` (output guard, outcome).
3. Tools: `search_reports` (`hybrid`, or r3 = period/stage filter on both candidate lists → RRF → top-30 listwise LLM rerank, fallback to incoming order), `get_series` (`StatsData.query` or the MCP backend), `calculate_change` (Decimal, half-up, same-series checks). Items get labels P/O/C and are sanitised (`sanitize_text`) and flagged (`injection_flags`). Items live in a per-run registry, not in graph state.
4. `answer/context.py` renders items as XML-escaped `<passage>` blocks; `answer/validate.py` checks label ∈ context, quote ⊂ item text (NFKC/case/space-normalised substring), quote ≤ 40 words, flagged items not cited, status/claims consistency. Numbers in claims not found in cited items go to a soft `ungrounded_numbers` list.
5. `finalize` scans only summary/reason/caveats/claim text with `scan_output`. `run_agent` returns outcome, answer, trace, usage, and writes `data/runs/agent/<id>.json` plus the audit record.
6. `report/app.py:public_result` projects the answer for the browser (`_bounded_answer` re-checks quotes, caps quote volume, rights window filter) and maps every non-`answered/abstained/clarify/refused` outcome to an "abstained" card.
7. MCP: `mcp/server.py` (9 read-only tools, 2 resources, 1 prompt, stdio or loopback HTTP + bearer), `mcp/client.py` (allow-list, schema validation before send, deadlines, size caps, sanitise/quarantine). The agent uses it only when `Shared.stats_backend` is set (`SyncStatsBackend`), default is direct.

## 2. Findings

### P0 (breaks a PDF requirement or the demo)

None found. The graph terminates, bounds hold, operational failures are not mislabelled inside the graph, tests are green.

### P1 (could mislead an assessor or silently corrupt results)

| # | Finding | Evidence | Impact | Fix |
|---|---|---|---|---|
| 1 | **Validated citations are dropped in the public result: 15% of validated quotes, 21% of answered runs end up with an uncited claim in the UI.** `validate.check` compares normalised text (whitespace, case, NFKC, curly quotes) but `_bounded_answer` and the card builder test raw `quote in evidence_text`. PDF passages contain hard line breaks, so a quote spanning one is valid for the validator and removed by the web layer. A second drop rule discards a quote already used by an earlier claim. | `report/app.py:115` (`quote not in str(evidence_text.get(label))`), `app.py:~160` (`q in text`). [F] Over `data/runs/agent/*.json` with `evidence_text` (2,161 answered runs): 5,194 citations, 802 not exact substrings, 196 duplicate-quote drops, 8 volume-cap drops; 633 of 3,894 claims (16%) lose every citation, 451 runs affected. Synthetic repro: validator `errors=[]`, `_bounded_answer` returns `citations: []`. | The demo shows "answered" claims with no visible evidence, contradicting the "every claim cited with verbatim quote" promise; an assessor will read it as ungrounded output. | In `_bounded_answer` and `public_result` reuse `validate.norm` for the substring test, then emit the original span from the evidence (locate by normalised offset) instead of the model's string. Allow the same quote on several claims (keep per-card word cap). Add a regression test with a quote crossing `\n`. |
| 2 | **Fabricated numbers pass the validator and are shown as `answered`.** The only numeric check is soft (`ungrounded_numbers`); it never adds an error, ignores years and the summary/caveats, and the quote check accepts any substring (no minimum length). The browser projection omits `ungrounded_numbers`. | `answer/validate.py:78` (substring), `:83-84` (soft list); `graph.py:278-282`. [F] Scripted run D: claim "Retrenchments rose to 9,999 in 2026-Q2" citing `O1` with quote `2026` → outcome `answered`, trace `ungrounded_numbers=['claim 1: 2','claim 1: 9999']`. `validate.check` on a claim with 9.9% and 12,345 citing quote `the` → `errors=[]`. Summary/caveat numbers are never checked. Docs state it is reported rather than rejected (`architecture.md` step 9), so this is a known design, but system card reports 7.6% of answers with the flag and the UI hides them. | The central "numbers come from validated records" claim is enforced by prompt only. A model failure or injection that survives yields a confident wrong figure. | Make ungrounded claim numbers a hard error (feeds the existing one repair; if still bad → `invalid`), require quote ≥ 3 words or ≥ 1 figure/period token for O/C items, run `numbers()` over summary and caveats against the union of cited items, and surface any residual flag in `public_result`. Re-run the dev set to measure the change before touching held-out. |
| 3 | **T-I06 crosscheck false-positive rewrites an honest answer into a wrong one.** `figures()` maps month names to a quarter via `period.parse`, so a monthly figure is compared with the quarterly dataset value. In the real corpus the annual job-vacancies report says the vacancy rate was 3.1% in December 2025; the dataset's 2025-Q4 value is 3.0. `annotate` flags a conflict and `enforce` replaces the model's correct claim and summary with an internal-id string for the quarter, with a one-token "quote" from the passage. | `crosscheck.py:46-61` (sentence → `parse(sentence).quarters`), `:158,171` (`text.split()[0]` as the quote). [F] Run over all 16,419 passages: 5 recognised figures, 2 conflicts; passage id `mom-jv2025:p008:b022:e97aa073` is the December/quarter confusion (a December monthly figure compared with the quarterly series). Repro: honest answer "job vacancy rate was 3.1% in December 2025" → `enforce` output: claim and summary become `job_vacancy_rate in 2025-Q4: 3% (validated dataset; source conflict).`, citations `O1 "3%"` and `P1 "1"`, `validate.check` passes. The other conflict (recruitment rate 1.8 vs 1.9 for Q3 2025, report vs dataset) is a plausible genuine disagreement. | Honest, correct answers are corrupted (wrong period, raw `source_id` leaked to users, caveat claims a conflict that is a definition difference); validators approve it. This is the exact path the owner added to fix T-I06, so an assessor probing a monthly figure will find it. Also reports the threat score as fixed while the guard has 1 false positive in 2 firings on real data. | Skip sentences whose period came from a month name (compare only explicit quarter tokens, `Q`/`1Q`/`first quarter`), or require the same granularity. In `enforce`, keep the model's claim, append the conflict as an extra cited caveat instead of overwriting, quote real passage text (the figure's sentence), and use the series title not `source_id`. Add a test with this passage. |
| 4 | **LLM calls inside the agent have no deadline; one provider stall holds the demo slot for many minutes.** The planner and answer calls use the default path (`timeout_s=None`): 180 s per attempt, 3 attempts, exponential sleeps. The planner can repeat once on bad JSON. | `graph.py:156,256`; `answer/llm.py:17-18,58-66`. [F] `chat(..., timeout_s=None)` takes the `httpx.post(..., timeout=180)` branch with `time.sleep(2**attempt)` retry on 429/5xx. [I] Worst case per call is 3 × 180 s plus backoff; several calls per run compound this. `report/app.py:50,415`: HTTP gives up at 90 s but the shielded task keeps running; `app.state.active` is only decremented when the thread ends and admission refuses at `active >= 2`. | A provider slowdown makes both demo slots unavailable (503 "Demo busy") for minutes after the first 504, and the 10 s tool timeout gives a false impression of a bounded run. During a live demo this looks like a hang. | Give the graph a run deadline (e.g. 75 s) and pass `timeout_s=min(remaining, 40)` to every `llm.chat` call (the deadline path already exists and is used by rerank); record the timeout as `operational_failure`. |
| 5 | **Quarantined MCP rows disappear silently on the agent route.** `McpStatsClient.get_statistic` returns `quarantined` but `SyncStatsBackend.query` returns only `rows`, so the agent gets a shorter series and `_coverage_notes` then says "the dataset has no row for <period>. Do not estimate it", i.e. an operational/security event is reported as missing evidence. | `mcp/client.py:450` (`return reply.rows, None`). [F] With the hostile fixture in `inject` mode (the fixture's own test server): client reports `rows=2, quarantined=1`; `SyncStatsBackend.query` returns the 2 rows, `calls` log has no quarantine field, no trace event. | Contradicts ADR-002 "operational failures are never reported as missing evidence" and the MCP client's own docstring for the quarantined kind. Only on the MCP route (non-default), hence P1 not P0. | Return a `ToolResult(False, error_kind=...)`/raise a non-correctable error when `reply.quarantined > 0` (or at least add it to the tool trace and a data-quality note). |

## 3. Verified OK

- **Bounds hold** (scripted doubles): 5 planned calls → 3 allowed per round, 2 rounds, 6 calls; third planner call never made; invalid answers get exactly one repair then `invalid`. Tool timeout (script C, 0.5 s limit, 3 s tool) ends `operational_failure` in 1.0 s with a clear error, not "no evidence"; timed-out work is not committed (fork/commit isolation).
- Passages are XML-escaped, attributes use `quoteattr`, flagged items cannot be cited, prompts tell the model to treat evidence as data; planner schema enums come from the catalogue; rerank output is enum-constrained and falls back to incoming order, never turns into a tool failure.
- No passage in the corpus is currently flagged by the injection heuristics (0 / 16,419), so honest evidence is not blocked.
- Retrieval period/stage hints: `Q4 2025 final` → only the final Q4 2025 documents; `advance` → advance only; no quarter → no filter. Chunk/passage ids trace back to source passages.
- Dense cache has all 1,847 current chunks; startup works offline. Cache writes are atomic and locked.
- Deterministic maths: Decimal, same-series/same-unit checks, zero-division handled, percentage points vs percent labelled; labels must come from this run's `get_series`.
- MCP: allow-list, loopback + bearer with constant-time compare, schema check before send, deadlines, size caps, typed result validation, row-level quarantine (counted at client level), resource schema validation; `evil.py` fixture exercised and quarantined as designed (apart from finding 5).
- Output guard blocks known secrets and the system prompt text; answers are only shown to the browser through `public_result`.
- Tests: 535 passed with `-m 'not corpus'`.

## 4. Three highest-value improvements

1. **Make the web projection match the validator** (finding 1): one shared normalised-span function; likely the most visible demo defect and with a regression test.
2. **Harden validation: hard ungrounded-number error, minimum quote length, numbers in summary/caveats, show residual flags in the UI** (finding 2). Re-run the dev cases to measure; also strengthens the "numbers come from code" narrative.
3. **Fix crosscheck period granularity and make `enforce` append rather than overwrite, then add a run deadline to every LLM call** (findings 3 and 4). Together they remove the one known path that corrupts correct answers and the one that can freeze the demo.
