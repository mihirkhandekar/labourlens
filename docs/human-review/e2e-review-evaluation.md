# E2E review: evaluation integrity

Scope: gold v3.x and the v2 draft, harness, judge cache, scorers, paired bootstrap, freeze protocol, post-run gold edits, `experiments/` artifacts, threat suite and refined scorer, corpus v1/v2/v3 labels, fresh-checkout reproducibility.
Method: read code, re-derived numbers from raw `data/runs/*` and committed `experiments/eval/*` with independent scripts, ran `uv run pytest -q -m 'not corpus'` (all passed, 53 s) and `gold.validate` on both gold files (0 errors). No model or network calls; no source/data/docs edited except this file.
Tags: **[FACT]** observed in code or artifacts; **[INFERENCE]** reasoning from facts, not run.

## 1. Flow as traced

1. **Gold.** `experiments/gold/draft_cases.jsonl` (HEAD sha `6169a9de…`, gold v3.6: 268 = 237 dev + 31 held-out, all authored by Claude agents; 45 `owner_reviewed`). Loader `retrieval/evaluate.py:load_cases(split, path)`; validator `retrieval/gold.py:validate`. v3.5 (`aac4b405…`) is the file the published metrics were scored on and is **not in the HEAD tree** (only in git history, e.g. `8b8c3a9`). v2 draft: `experiments/gold/heldout_v2_draft.jsonl` (65 cases, sha `69894035…`, matches `experiments/heldout-v2/FREEZE.md`).
2. **Generation.** `labourlens agent-exp` → `agent/experiments.py:run` → `agent/graph.py:run_agent` per case, 3 workers. Raw runs go to gitignored `data/runs/agent-<split>-<tag>/<model>.jsonl` (include answers and evidence text); scores to `experiments/runs/agent-*/`.
3. **Scoring.** `labourlens eval` → `evaluation/harness.py:run`. Per run record: join gold by `case_id`, skip if `question` text differs (`harness.py:~198`), `cached_judgement` (key `judgement_hash` = question + reference facts + expected behaviour + exact judge payload + judge model + judge-prompt hash) → `judge_one` (`gpt-6.1-terra`, `prompts/judge_v1.md`) → `case_metrics` (`agx.score_run` → `answer/experiments.py:score` + `_calc_correct`) → `aggregate` (bootstrap 2000, seed 7) → `experiments/eval/<exp>/<model>.{cases.jsonl,metrics.json,judgements.json}` + `<exp>-REPORT.md`.
4. **Paired.** Registered original held-out: `experiments/heldout/paired.txt` (n=31, 10,000 resamples, seed 20261030), produced by an ad-hoc script not in the repo. v2: `evaluation/paired.py` / `labourlens paired` (numpy, seed 20261031, 20,000 resamples, 97.5% intervals), reads only `experiments/eval/<exp>/<model>.cases.jsonl`.
5. **Retrieval study.** `retrieval-exp2` → `experiments/runs/dev-R*/` (`scores.jsonl`, `metrics.json`) → `dev-R-summary.json`; gold hash `647b26a2…` (v3.2).
6. **Threats.** `security/threat_suite.py` over `experiments/threats/cases.jsonl` (36 hand-written cases) → `experiments/threats/runs/` (frozen) and `experiments/threats/m7-ti06-postfix-20261031/` (post-fix, strict + post-hoc refined).
7. **Report/site.** `report/build.py` projects committed artifacts into `web/static/data/report.json`; `docs/evaluation-report.md` is hand-written.
8. **State.** Judge cache is `experiments/eval/<exp>/<model>.judgements.json` (committed). Raw runs, passages and indexes are local only. Corpus snapshots: `experiments/corpus-snapshots/v1|v2|v3.json`.

## 3. Verified OK (checked, no defect)

- **Five headline numbers independently re-derived from raw `data/runs` (own script, not repo code):** behaviour accuracy A1/A3/A5 dev and H-r3/H-hybrid held-out for both luna models (all 10 match, to 3 dp); over-abstention and false-answer rates match, and the false-answer denominator note in the report is accurate (`false/(n−over-abstain)`); retrieval R0–R3 hit@8 (0.5703/0.8438/0.7891/0.9688) and MRR@10 (0.3244/0.5421/0.7643/0.9121) from `dev-R*/scores.jsonl`, n=128; paired R3−hybrid with the registered seed (0.161 [0.000, 0.323], 0.097 [−0.032, 0.226]); claim support 274/309 = 0.887 (A3 luna6) and fact coverage from the judgement cache.
- **CIs:** A3 behaviour [0.865, 0.937] recomputed with the same percentile bootstrap; percentile indices 50/1949 of 2,000 are right; pooled ratios resample cases, not claims (as documented); Wilson intervals in the threat table recompute exactly (35/36 → 0.858–0.995, 34/36 → 0.819–0.985, 32/36 → 0.747–0.956). `paired._interval` clusters groups and weights by group size correctly.
- **Report tables vs artifacts:** all 210 numeric cells in the dev and held-out result tables of `docs/evaluation-report.md` match `experiments/eval/*/*.metrics.json`. Failure-ID tables for A3 (7/7/9 split = 23) and registered held-out (per-arm IDs) match `.cases.jsonl`. All 21 `evaluation.rows` metrics in `report.json` are byte-equal to the metric files (two held-out gpt-4.1-mini files are omitted, consistent with "unregistered/excluded").
- **Judge cache:** fingerprint covers question, reference facts, expected behaviour, exact payload, model and prompt hash; stale entries are re-judged, including with `--no-judge` (not reused). Judgement counts equal the case rows.
- **Leakage:** v2 shares **0** source ids and **0** evidence ids with dev+held-out gold and has no duplicate question text (max token-Jaccard 0.55, DEV-634). No gold question has a 5-gram in `prompts/`. The original held-out overlap (25/31 share an evidence id, 14/31 fully inside dev ids, 2 with no evidence; 29/31 sources in dev sources) matches the report/D-039; the report calls it question-held-out only. Gold is not passed to the agent (the oracle path is used only by the G0 study).
- **Registered rule vs result:** the original held-out comparison honestly reports inconclusive; post-run edits (HO-029, HO-027, HO-023, HO-004, HO-022) are versioned, hashed and sensitivity-tabled. HO-022's relabel raised all four arms by one case (paired effect unchanged) and HO-029/HO-027 lowered or held scores.
- **v2 gate files:** gold sha, `v3.json` snapshot, passage fingerprint (recomputed), and `components.json` agree with `FREEZE.md`; 22 evidence components, 39 total, 48 evidence-bearing cases, behaviour mix 44/8/5/4/4 as stated. `gold.validate` returns no errors for both gold files.
- **Scorer inflation risks looked for and not found:** operational failures stay in the denominator; `a is None` is a miss; non-answers cannot earn gold-cited credit through the "any one id" rule beyond what is disclosed.
- **Threat suite:** the poisoned fixture exercises both candidate lists; zero not-exercised cases; the strict result is preserved beside the refined one, and `rescore` refuses to touch frozen runs.

## 4. Three best-value improvements

2. **Fix the report/site drift** (P1-4, P1-5, P2-6, P2-7; about 45 minutes): update the evaluation report's threat section to the D-038/post-fix facts, keep the strict score as headline, and source the error panel from the rescored case files.
3. **Re-tune the v2 rule before any model call** (P1-6, P1-3; about 30 minutes): per-model α 0.05 (or one primary model), count-based false-answer clause, record HEAD, crosscheck setting and prompt hashes in a committed `FREEZE.md`, and publish the power table above as a pre-registered statement.
