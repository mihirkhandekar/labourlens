**Review type:** blind independent AI review, not human review. **Date:** 31 October 2026. No gold labels or human-review fields were changed. This report is advisory for the owner’s subsequent adjudication, not a new approved gold version.

## Scope and independence

Reviewed all **31 held-out cases** and **40 development cases** in `experiments/gold/draft_cases.jsonl`. The dev sample includes all nine populated `context_only_evidence_text` cases and every required non-answer behavior. I did not open the prohibited review files, gold history, or study notes. The gold schema contains `ai_review` and `ai_review_2`; their values were deliberately excluded from displayed/inspected fields. An initial short file preview exposed evidence-provenance wording mentioning an earlier AI review, not its verdict. README states that earlier AI rounds occurred; no previous case verdict was inspected.

**REQUIREMENT:** use evidence-supported behavior, deterministic arithmetic, and the hard 2024-Q1–2026-Q2 analysis window. README line 5 explicitly extends abstention to mixed-period comparisons that need an earlier endpoint. Consequently the nine context-only cases remain abstentions even where their in-scope subpart is available. Contextual methodological definitions and cohort metadata are not themselves requests to analyse an older quarter. Security-only secret disclosure/exfiltration requests remain refusals; an answerable public component should still be answered safely.

**VERIFIED FACT:** assessment requirements concerning leakage, evidence citations, uncertain/out-of-scope questions, and human evaluation were read directly in the assessment PDF. README, ADR-001, ADR-002 and the ingestion plan were consulted for project boundaries; a plan was not treated as execution evidence.

## Sampling method

Used Python `random.Random(20261031)`. Begin with the nine context-only dev records in original file order. For each family in alphabetical order, draw uniformly from remaining records sorted by `case_id` until that family has at least five cases. In order `abstain`, `refuse`, `clarify`, `ignore_injection_and_answer`, add one uniformly sampled case only if that behavior is still absent. Draw the remaining slots uniformly from all unselected dev cases sorted by `case_id`, to reach 40. Sort the final sample by `case_id` for presentation. This is constrained stratified random sampling, not a claim of an unconstrained simple-random sample.

## Leakage and interpretation observations

Ordinary source names, quarterly dates and indicator groupings are legitimate disambiguators, not answer leakage. Revision/conflict questions may intentionally supply competing figures; HO-020 and DEV-332 therefore test reconciliation, not independent recovery of all supplied numbers. HO-014 supplies the direction of the ratio and should not be credited as an independent test of discovering that direction. Explicit attacks in HO-027/028 and DEV-501/504/508/512 are legitimate security probes, but the three exact-tenfold substitutions in I-05 permit a non-retrieval correction shortcut. No claim is made that a tested system actually used such a shortcut.

In I-02, the ambiguity is publication vintage rather than arithmetic. In I-03, the issue is whether a helpful source-backed correction must be forced into clarification; the current label is defensible if the rubric requires an explicit comparison period before any corrective explanation. Neither doubtful case should silently become a new held-out target after results have been inspected. Owner adjudication should version any amendment and preserve prior results.
